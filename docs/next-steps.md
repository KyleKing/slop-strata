# Remaining work

Checked against the code at 61b2aba. Items from the v0.6.0 audit that are now done are left out.

## Output that misleads

- `history` text omits the pairing rows. They are JSON only.
- `history` does not group changes by reading. Only `change` prints a reading.

- Module depth matches a method by its name, with no type of the receiver. A method named like an unrelated member that another directory reads (`get`, `String`, `value`) counts in `shown_by_name`, so `depth` is a lower bound and `depth_attributed` an upper one. On a 53-method sample 20 were matched only by such a collision. Counting only calls, and treating properties apart, would narrow the range.
- Module depth counts a declaration per file, so a Go name declared once per platform (`util_unix.go`, `util_windows.go`) counts twice.
- Module depth reads a library's public API as hidden when only tests and the outside world use it, since test files are not users.
- The directory table runs past 100 columns on deep paths. The depth table shortens a path in the middle, and two directories can then read alike.

- `history` samples the import graph once per week. A cycle that comes and goes inside one week is never seen, and a cycle that goes away for a week and comes back is dated to its return.
- A cycle's introducing commit is a first-parent commit, so a merge commit stands for its whole branch. The author class is the walk's, and a squash that carries a bot's co-author trailer reads `bot`.
- `median_depth` is taken over the directories with five or more names, often a handful, and jumps when one directory crosses that line.
- Hidden coupling lists few pairs: 7 across twelve public repositories at the shipped floors. It leaves out every pair of TypeScript files in two workspace packages, because a package-name import adds no edge. Resolving workspace package names in the import graph would let those pairs be judged, and would change the cycle counts too.
- Hidden coupling treats a file as production when the path rules do. `test.ts` beside its subject (date-fns) and `__testfixtures__` inputs (query) are not recognised as tests, and pair under looser floors.
- Hidden coupling reads intent from the commit subject. A typing or lint sweep with no Conventional Commit type counts, and two such pairs (requests, chi) sat just under the support floor.
- `history` resolves a graph for every sampled week on every run, which about doubles a warm run (TanStack Query over three years: 4.1 s to 9.2 s). Storing each sampled commit's cycle sets and depths in the cache, keyed by the commit and the digests of the packages that compute them, would leave a warm run only the last tree to read.
- The `history` walk stores blobs under the abbreviated ids `git log` prints, so `snapshot` and `history` do not share cache entries for the same blob. The architecture pass maps the ids for its own lookups. Asking the log for full ids (aragonite) would remove the mapping and the duplicate entries.

## Rules below the bar

`slop-strata label` records verdicts per repository and `slop-strata rules` prints each rule's labeled precision, but the gate is still a judgment call on the corpus. Label more findings across repositories, record precision per release, and move a rule out of the gate only on that evidence. `slop-strata --explain experimental` lists the gated rules.

- `go/silent-error` flags any blank last target on a sole call. Flagging only discarded errors needs callee types, which the rule does not have.
- `x/narrating-comment` is still gated. Drop it, or keep it gated, once labels across repositories show its precision.
- `x/dead-export` skips Go methods, which avoids interface false positives. It does not resolve interface satisfaction.
- `snapshot` reports `x/stale-prose` for every unresolved name, behind `--experimental`. It should flag only names the history shows existed and are now gone. The exemptions for changelogs, ADRs, and migration guides already exist.
- `x/import-cycle` is gated until its hits are labeled. On eight public repositories it reported the same components as an independent resolver, but TypeScript path aliases and workspace package names add no edge, a value import that is only used as a type still counts as a runtime edge, and Python imports of a submodule do not count as importing its parent packages.
- `x/dead-export` and `x/could-be-private` cannot tell a library's public API from an export nobody wants. They skip what a manifest, an `__all__`, or a whole-module re-export publishes, and still report a name a library exports from a file its entry point imports by name. That is why Go types, constants, and variables (10 of 23 sampled hits real) and TypeScript classes (0 of 4) are recorded and not reported. Following re-exports from each manifest entry to the names it publishes, and treating a Go package outside `internal/` and `main` as importable, would let those kinds in.
- The same two rules count a reference by name in any file the tool parses. A name imported only from a `.vue`, `.svelte`, `.mdx`, `.js`, or `.mjs` file reads as unused (3 of 7 false positives in a sample of 40), and so does one a framework reaches through a namespace import.
- Chained and tuple assignments at module level in Python (`a = b = 1`, `a, b = 1, 2`) declare names the fingerprint does not record.
- `x/last-ref` asks whether any declaration of the name is left, not whether the one the change stopped using is. Over the last 200 commits of six repositories it reported 11 findings, 7 of them a helper the change left behind and 4 a name some unrelated file also declares (a Next.js page component, a test fixture). Before the declaring file's own uses counted and an exported declaration was discounted once, the same commits gave 28, and none of the 12 sampled was unused. Attributing the name through the import graph would settle the 4.
- `x/new-duplicate` is gated. On 3,750 commits of 15 public repositories it gives 6.3 findings per 100 commits, and of the 131 that are labeled 48 are real, 71 plausible, and 12 false: 37% by the strict reading and 91% with the plausible ones. One person labeled them, and only 8 are Python. The false ones are files that are parallel by design and that no path rule names (one locale per file, two flavours of one API, a config per package, an integration app), a guard repeated on purpose after taking a lock, lines two sites share by chance, and a two-line idiom. Labels from more than one reader, and more Python, come before any move out of the gate.
- `x/new-duplicate` finds few of the repeats that later get merged: 23 of 152 mined consolidation commits at its floor, and 5 of 68 when replaying the commit that wrote the later copy. See "Duplication, after the second stage".
- `py/type-any` and `go/type-any` report every hit. They should report a count per file. `go/type-any` already skips generic constraints and variadic `...any` parameters a function spreads into a call, and leaves fields that hold JSON of unknown shape to labels.

## Dodges the rules lose to

Each of these is a variant in `Gaps` of an adversarial fixture (`internal/rules/adversarial_*_test.go`, `cmd/slop-strata/lastref_test.go`), which asserts the rule reports nothing. Closing one fails its test until the variant is moved to `Dodges` or `Persists`.

Needs types or a call graph:

- `go/silent-error`: call the function bare, or hand its error to a function that ignores it
- `go/type-any`: a type parameter constrained by `any`, which the rule exempts on purpose
- `go/test-reads-source`, `py/test-reads-source`, `ts/test-reads-source`: read the file through a helper or fixture that takes the path, `import` the JSON, or bind a computed path to a name first. Only a name bound once to a string literal is read through: reading through any binding added 6 hits, 4 of them test data found from `__file__`
- `go/timing-hack`, `py/timing-hack`, `ts/timing-hack`: sleep in a helper outside the test files or under another name (`from time import sleep as pause`, `settle(50)`, `timers/promises`), or wait on an event nobody sets. Two TypeScript sleeps are left alone because most hits were a simulated delay inside a handler or a query function and not a test waiting on time: a bare `sleep(n)` (1,916 hits on four repositories, 1,909 of them in one) and `new Promise(r => setTimeout(r, n))` (78 hits, 7 of 20 sampled a test waiting)
- `py/type-any`: `Any` under another name, behind a module-level alias, or in a quoted annotation. `ts/type-any`: an implicit `any`, or `object | Function`
- `py/mock-patch`, `ts/module-mock`: `patch` or `vi` under another name, assigning over the attribute by hand, or `vi.spyOn(...).mockResolvedValue`
- `ts/as-unknown-as`: widen through a variable annotated `unknown`, or cast inside a generic helper
- `ts/record-unknown`: `Map<string, unknown>`, `object`, or an index signature. Matching `[key: string]: unknown` added 33 hits, and about 5 of 20 sampled were a type with nothing but unknown values: the rest were open objects with named fields or the expected side of a type test
- `x/single-impl-iface`: a second method or member, an unrelated type sharing the method name, or no `implements` clause

Needs a judgment the rule does not make:

- `py/silent-except`, `ts/silent-catch`: return a default from the handler, `contextlib.suppress`, `void err`, or a comment in the `catch` block. The comment is the documented-intent case and is left alone on purpose, as ESLint's `no-empty` leaves it: 59 corpus blocks carry one, each saying why
- `py/or-default`: `if not rows: rows = []`
- `py/mock-only-assert`, `ts/mock-only-assert`: copy the call record into a variable first. `assert mock.called` and `mock.call_count` are left alone, since hand-written flags and counters carry those names. `expect(...).rejects` and `.resolves` are not read as assertions, which is 3 of the 4 false hits in 35 sampled
- `py/constant-echo`, `ts/constant-echo`: wrap the constant in a call, use `assertEqual`, copy it into a local, use a looser matcher, or read it off an object. The last is left alone: `expect(process.env.X)` and `expect(schema.enum.A)` were all five corpus hits
- `x/ignore-without-reason`: a reason of one character
- `x/case-table`: two tables of eight, or the records in a list
- `x/comment-density`: move the comments above the function or into the docstring, fold them into one block comment, or pad the body with blank lines. Counting comment lines over non-blank lines closed the last two and added 98 hits, of which a sample of 20 was mostly explanation, commented-out code, `@ts-expect-error`, and `@see` blocks, so the count is as it was
- `x/clone-function`, `x/dup-test-case`: one extra statement, a docstring, a dropped return type, `it.only`, or a move to another file (which `x/clone-function` then reports)
- `x/dup-literal`: name the literal in one file, which takes the count under four
- `x/new-duplicate`: rename more than three things in every stretch of the copy, or a name or two in every statement of a copy whose statements no longer sit in a row. A copy with its loop rewritten as a comprehension or a chain of calls, with two statements swapped, with a line added after each statement, or with one left out is still reported, and those are `Persists` variants. A repeated expression is lost when it is taken apart over several statements, when the two sides of a sum are swapped, or when four of its names change
- `x/new-case-set`: split the cases over two switches of two each, or reach them through local aliases. A place moved to another file, renamed, written as a chain or a table in place of a switch, or left one case short is still reported, and those are `Persists` variants
- `x/new-jsx-shape`: use another tag for one element, add an attribute to one, or add one child. Any of them is another shape, and the pass has no near miss. Other text, other attribute values, another indent, and a comment change nothing, and a copy under another component name, in another file, or inside a wrapper is still reported, and those are `Persists` variants
- `x/new-sibling`: rename one of the two shared methods, which leaves one member in line, or write the methods as functions of a module, which is another kind of container. Another table name, a renamed local, a comment, one more statement in a method, and a method of its own change nothing, and a copy under another class name or in another file is still reported, and those are `Persists` variants

Matches a name and nothing more:

- `x/dead-export`, `x/could-be-private`, `x/unused-option`, `x/last-ref`: a reference from a test, an unrelated identifier with the same name, an import left unused, `__all__`, a decorator, or a whole-module re-export. The last three are the exemptions that keep a library's API quiet
- `x/single-entry-registry`, `x/narrating-comment`, `x/spent-test`, `x/unused-option`: a word outside the rule's vocabulary, a registry filled after it is created, or a narration moved into a docstring
- `x/stale-config`, `x/stale-prose`: the key or the name kept alive in an unrelated identifier or string, a negation in front of the name, or a fenced block

`py/silent-except` and `ts/silent-catch` treat a comment differently, as they did before these fixtures. In Python a comment on its own line above `pass` sits outside the handler's block in the grammar and the handler is reported, while `pass  # reason` is not. A comment that only silences a linter (`pass  # noqa`) is now read as no reason. In TypeScript any comment in the block clears the finding.

## Duplication, after the second stage

`x/new-duplicate` lines up whole statements of equal shape, adds up the short stretches two functions share, and looks up expressions of 20 tokens or more. What the 153 mined consolidation commits still show it missing, and what the second stage learned about each. The commits, the matched pairs nobody merged, the hand labels, and the scripts are kept in [eval/consolidation](../eval/consolidation/README.md), so a change to the rule can be replayed against them:

- Fragments under the floor. Most mined repeats are one or two short statements or one short expression: 102 of the 152 have a median site under 25 tokens. Dropping the expression floor from 20 to 10 finds 36 of the 152 in place of 23, and 9 of the 68 later sites in place of 5, and at 15 to 20 tokens the findings on real changes were 2 real, 7 plausible, and 7 false of 16. Tokens alone do not separate those. Signals that might: the two sites edited in the same commits, a third or fourth copy appearing, the expression being the whole right-hand side of a named value somewhere, or an existing function whose body is exactly the expression (one sampled finding repeated the body of a helper that was already there).
- Stretches that add up to under 20, which were 4 real, 4 plausible, and 4 false of 12 between 12 and 20. Joined stretches found none of the mined commits at any floor, since those are small and contiguous, and are kept for what they find on real changes: 8 real and 10 plausible of 19.
- A repeated expression that is not one subtree. `a || b || c` inside `x && (a || b || c)` is a subtree, and inside `x || a || b || c` it is not, because the operators group to the left. Matching a run of tokens in place of a subtree would reach it, at the price of an index over token windows.
- An expression in a signature, such as a parameter type written out in five functions, is never reported, since counting signatures made every pair of overloads a finding. Several mined commits are exactly that: a type alias replacing a repeated annotation. A rule for types alone, by exact text and count, might hold up where the general one does not.
- An expression that holds statements gets no record, which leaves out a call wrapped around a callback even when the callbacks match. The statements of matching callbacks still line up as a run.
- Sibling classes. Methods of two classes that share a base or an interface line up only as far as their statements do, and nothing compares the member lists of two classes or reads which base they share. Members of two types do add up between the two declarations when each member is a statement of its own.
- Many to one. A new function whose statements are covered by two or more existing functions, or several new functions that together repeat one, is reported once per pair or not at all. The pass has the stretches per pair of functions already, so coverage by site is a sum over pairs with one side fixed. It was not built: nothing in the mined commits has that shape, so there is no replay to set its floor on.
- A function pair a run already reports keeps the stretches around that run out of the finding. Folding them in would say how much of the function is a copy.
- Tests, examples, and benchmarks are left out whole. A test helper copied between two test files is a real case, and it is 12% of the mined commits.
- The snapshot list of repeated code is built as `duplicate_groups` and gated. Of the top five groups of twelve repositories 32 were worth merging, 16 a judgment call, and 12 not, and Python (45% and 75%) and TypeScript (45% and 65%) are under both bars. Seven of the 12 are files kept parallel on purpose: a locale per file, an adapter package per framework, a config per package, two flavours of one API. A workspace package boundary, or a set of sibling files that each hold a unit of one name, could mark those, and neither was tried. The others are declarations a `TypedDict` and its class both need (a rule for stretches that are only annotations), public wrappers whose body is one forwarding call (module depth already records a function that only forwards its own parameters, and a literal argument breaks that test), and demo code under a main guard. One person read every group, and the three guards the list added were chosen on the repositories the labels come from, so labels from a second reader and from repositories outside the twelve come before any move out of the gate.
- `duplicate_groups` does not say which site to keep, and it does not add up stretches two functions share with other statements between them, as the change rule does. The idiom rule applies as it does to a change: a statement whose shape the tree holds in 33 places or more weighs nothing, so a block copied into forty files is not listed.
- Two files in different languages can be paired, since a shape hash does not know the grammar it came from. None was seen in the replays.
- The fingerprint walk is 22% to 29% slower than before the statements were added, because it visits every token, and the blob cache is 30% to 69% larger (the README has the tables). The expression records added 1.3% to 2.5% more. Two bytes of the exact hash would do for what it is read for, and the names repeat what `Referenced` already holds.

## Split candidates

`snapshot --experimental` lists the functions a split would relieve most, with the block to move. It was on by default in 0.19 and is gated now: of the top five in twelve public repositories 42 of 60 could move as they stand (34 before scopes and the exit rule), and 23 of the 40 nobody had read before, against a bar of 80%. A third round took the twelve to 45 of 60 and read 20 of 43 on ten repositories held out from it. What the readings and the replay showed:

- The counts are no longer the common failure. Names resolve to scopes, closures count what they take, and receivers do not count. Two cases are still wrong: a variable one arm of a branch writes and another arm reads is not an input, and a variable a loop body writes on one pass and reads under another branch on a later pass is neither input nor output. Both need the walk to know which writes reach a read, per path, where it now has the order of the code and a nesting depth.
- A write through a field or an index is a read, so a block that fills a map or mutates an object it was handed shows no output. That is right for extraction and wrong as a measure of coupling.
- A block that reads exactly 5 variables was `yes` in 8 of 17 candidates, against 34 of 43 with 4 or fewer. A bound of 4 is in place now. By itself it left the top fives of the twelve at 42 of 60: the 17 candidates that took the place of the 17 it removed were 8 `yes` and 9 arguable.
- Nothing past the fifth rank of a list was read. Small blocks in functions near the floor are the likely weakness far down one. Raising the floor of 5 on both sides, or of 15 on the function, would cut them and has the same need for new labels.
- A part of a block is held to 4 statements, which stops a cut that balances two halves and makes a new miss: three candidates were cut one statement after the declaration of the list they fill, or one statement into a loop body because that scored a point more than the whole body. Taking a declaration with the block when the block is its only reader, and a whole body over a part within a point or two, would remove them.
- Parallel blocks are still cut through: two of several like sections, or the last arms of a chain of like checks, were 4 of the 18 misses. The duplicate pass already knows which statements have one shape, and a run that ends between two statements of one shape could be passed over.
- The ranking is by the size of the cut. The share that could move as they stand was 75%, 92%, 75%, 50%, and 58% from the first rank to the fifth. Ranking by drop per variable crossing the cut was not tried.
- Of 36 commits whose subject and diff look like an extract-method, the function was listed at the parent in 11, against 14 before these rules, and the block named overlaps the lines moved in 4, against 7. One candidate per function is listed, and the second and third best are not kept.
- Functions under a cognitive complexity of 15 are not read. Five of 19 extract-method commits split a function under it.
- The split search runs for every function that qualifies whether or not `--experimental` asks for the list, since it is stored with the blob. It costs up to 0.2 s on a cold run of 3,163 files, and the scope pass adds 15% to 30% to the parse of a file whose every function qualifies.
- The second reading was by the person who chose the rules. A reading by someone else, on repositories outside the twelve, is what would move the list back to on by default.
- A third round added three rules (at most 4 inputs, a run that is some of a list of like-headed branches, a run that leaves behind a declaration only it reads), froze them, and read the top five of ten public repositories no split had been read in. The twelve went from 70% to 75% and the ten from 39% to 47% (20 `yes`, 19 arguable, 4 `no` of 43), so the list stays gated. DESIGN.md section 9 has the table, and `eval/consolidation/labels/split-candidates-v3.tsv` the 119 verdicts behind it, 39 of them copied from the second reading.
- Tried in that round and not kept, each scored on the labelled candidates of the twelve: inputs and outputs together at most 4 (46 of 60 against 45, 24 fewer functions listed), no exit at all (74% of the labelled, 305 listed), at most 3 inputs (73%, 328 listed), no whole loop body (73%, and 4 of 11 labelled loop bodies were `yes`), a block of 8 or more by itself (74%, 295 listed), and sections told by the shape of the whole statement to a depth of one or two. A sections rule that read loops as well as branches passed over a function of two unrelated loops. No guard on what the walk already counts moved the held-out share by more than its noise.
- The next gain is in the counts and not in a guard. Of the 23 held-out misses, 5 were an output that went uncounted because the next line to name the variable writes it: the other arm of a branch, the next of several checks that set one flag, a `continue` that hands state to an outer loop. A run that always returns is taken to have no outputs even when a `continue` in it leaves the function running. Five more started after declarations the run fills: a `var` with no value, a list that is read again afterwards, or a variable one branch writes and the condition of the next reads, which is not an input because the walk gives a condition the depth of its arm. Outputs need the writes that reach a read on some path, and leading declarations need to travel with the run that first writes them. Both together bound the gain at 30 of 43, which is 70%.
- The other 13 misses are halves of a loop body or an arm, whole loop bodies, and one of several sections whose headers differ. Nothing the walk has tells them from a step, so 80% may not be reachable for this list as it is ranked. Two things not tried: ranking by drop per variable across the cut, and listing only whole arms, which on the held-out ten were 8 `yes` of 13.

## Case sets

`case_sets` and `x/new-case-set` are built and gated. What they leave open:

- One person read every family, by a reading wider than "worth merging": a set counts when it is real and nothing ties it together. By it 23 of the 30 families of ten repositories no guard was fitted to were yes and 6 a judgment call. Labels from a second reader, and a narrower reading that asks whether a table or a type would replace the places, come before any move out of the gate. Python has 9 families in all, and 14 of the 16 fresh TypeScript ones are one design in date-fns
- A change that adds a case to some places of a family and not to the rest is not reported. The list carries what a rule would need, `missing` and `default` per site: match each place of a changed file before and after by its unit and kind, take the cases the change added to it, and report the family's other places that still lack them and have no default arm. It was left out because nothing has measured how often such a place is wrong. A place that handles a subset on purpose looks the same as one that forgot a case. Replaying commits that add a case to one site, and reading whether a later commit adds it to the others, would say
- A case more than 40 places name joins nothing, so a set a whole compiler switches over, a node kind in a hundred visitors, is not listed. Neither is a set of fewer than 3 cases
- Places are joined by the cases they name and not by what they test. Two switches over different things that share three strings are a family: direction words in fzf, status words in TanStack Query, field names a backend and a frontend share by chance. `weight` ranks them low and does not remove them. The type of the subject would settle it, and the fingerprint has no types
- Go: the kinds of the `reflect` package are constants like any other, and a switch over `reflect.Slice` and `reflect.Struct` is a check for a builtin shape more than a set of the program's own. Three of the 12 Go families of the ten fresh repositories were such, 1 `no` and 2 plausible. They were not dropped as the builtin types are, because that guard would have been fitted to the sample it was seen in. A literal of a named map type (`Names{KindA: "a"}`) is not read, since a struct literal is written the same way
- TypeScript: an interface implemented as an object of arrow functions still reads as a table (the 1 `no` in trpc), where one written with methods does not
- Files kept parallel on purpose are not set aside: one function in two files under build tags (gin), an ordinal function per locale (date-fns), a table per theme (rich). The duplicate pass's test for two files of one name that are 80% alike is not applied here
- `x/new-case-set` is rare: 12 findings in 4,787 commits of 22 public repositories, 8 of them yes and 4 plausible by the family each joins. That is too few to say what its precision is, and none was read against what the author did next. A change that writes every place of a family at once is not reported
- A subject compared through a helper (`is_admin(role)`), a chain of `startswith` tests, and a dispatch through a registry decorator are not read

## JSX groups

`jsx_groups` and `x/new-jsx-shape` are built and gated. What they leave open:

- One person read the groups. Of 51 among the 20 listed in each of five public React applications 37 were yes and 14 a judgment call, and of the 20 in the two applications no guard was fitted to, 13 and 7. Lower in a list it is weaker: ranks 13 to 20 of four of the lists were 9 of 20 yes, and nothing past rank 20 was read. Labels from a second reader on applications outside the six come before any move out of the gate
- No recall is claimed. The pass has not been replayed against commits that extracted a component. A block of under 6 elements is under the floor, and where the repeated thing is a hook or a line of logic there is little markup to find. A lower floor lists several times as many groups and was not read
- No near miss. Two blocks that differ in one tag, one attribute name, or one child are two shapes. The prototype's looser shape (component tags all alike, attributes dropped but for handlers, a lone `div` or `span` wrapper read through) found twice the groups and every false one it read. Anti-unifying the pairs that share one large block, as `x/new-duplicate` joins stretches, is the version worth trying
- The gate is one hole per element, taken from the prototype, where it was read off the labels it was scored on. The weakest groups read here sit at it: two sites whose every element differs in a value, such as two confirmation dialogs. A gate under 1.0, or one that asks for a rank above 0, was not tried, because it would have been fitted to the sample that showed it
- Loading skeletons and placeholders are 6 of the 14 judgment calls: rows of `Skeleton` or `Loader.Item` that two views write alike. They are real repeats and a maintainer may still want each view to own its placeholder. Nothing sets them aside
- Skeletons a component library dictates (a dialog with a header and a footer, a menu with a trigger, a form field with a label and a control) pass when the sites fill them alike. The prototype's false ones were all of this kind, and the hole gate is the only guard against them
- A group of several blocks gives the lines of one. `blocks` counts the rest and `elements` and `holes` sum them, and the sites of the others are not listed
- It overlaps `duplicate_groups`. A block that is the same down to its values is also a repeated expression of 20 tokens or more, so one copy can be two rows of a snapshot, and neither list reads the other. On `change` it is one finding: an `x/new-duplicate` finding whose lines an `x/new-jsx-shape` block covers is dropped. The deferral is by lines alone, so a duplicate inside the new block that repeats code somewhere other than the block's twin is dropped with the rest, and an ignore or a baseline entry on the block hides both
- Files kept in step on purpose are not set aside. The duplicate pass's test for two files of one name that are 80% alike is not applied
- Only JSX is read, in `.tsx` and `.jsx` files. Markup in a `.js` file, built with `createElement` or `h`, or written in a Vue or Svelte template is not, and neither is repeated logic with no markup: hooks, `useQuery` and `useForm` wiring, column definitions
- A handler written in place and one passed by name are the same hole, and a hole's value is kept as 16 bits, so two values in 65,536 read as one
- `x/new-jsx-shape` is rare outside one repository: 23 findings in 1,500 commits of six public applications, 17 of them in documenso. Five of the 23 join a group that was read, 4 a yes and 1 plausible, and the other 18 were not read, so nothing says what its precision is. A new form whose fields each join a group of their own is one finding per field. None was read against what the author did next. A block edited until its shape matches another that was there is reported only when the change also rewrote its first line

- One person read 34 sets, the top five of each of the twelve repositories that list any: 23 yes, 8 a judgment call, 3 wrong. The four applications, read after the rules were fixed, were 14 of 19 yes and none wrong, and the eight libraries the last guard was fitted on 9 of 15 and 3 wrong. Only 2 of the 34 are Go and 5 Python. Labels from a second reader, on more Python and Go, and past the fifth rank come before any move out of the gate
- It lists few sets, and no recall is claimed. Fourteen of 22 libraries and two of six applications list none. The floors were not moved after reading, and a lower set (three members of 12 tokens, 40 shared tokens, a quarter of the smaller container) was not read, so nothing says where the better trade is. A single large function copied per module is not a set: two members are needed
- Members pair by name. A sibling whose methods were renamed is not seen, and a second index, on the hash of a whole member, is not built
- Names that more than 40 containers hold propose no pair. In a large route tree every file exports `GET` and `POST`, so two route files copied from each other are found only when they also share a rarer name, and in a small one (umami, documenso) they are found. The cap is on the tree, so the same code is listed or not by how large the repository around it is
- An interface implemented once per vendor, per event, or per locale looks the same as a copy: same member names, same statement shapes, other strings. date-fns's locales are the one such set read. A rule on what differs (strings alone) cannot separate them, because a real copy also differs in strings. What would tell them apart is whether the members override an abstract method, which needs the class hierarchy
- Two flavours of one API in two directories (zod's classic and mini) are caught only when the files have one name and are 80% the same as written. The two that got through differ in every type name
- The clustering is a star around the heaviest container, so one family whose members come in two variants is two or three sets. Merging sets whose hubs join each other was not tried
- `rank` charges nothing for parameters. The pass compares statement shapes and does not read the slots, so it cannot count the names two members differ in as `duplicate_groups` does. `differing` counts statements, and a set whose statements all line up may still differ in twenty literals
- It overlaps `duplicate_groups` and `x/new-duplicate`, and nothing hands off. Of the 34 sets read, 26 have a duplicate group at two of their sites, 10 among the 20 a snapshot lists. On `change` a copied class is one `x/new-sibling` finding and usually one or more `x/new-duplicate` findings on the same lines. The duplicate rule could defer here as it does to `x/new-jsx-shape`, when its match is a sibling of the set, and that was left out because the duplicate finding is the more exact of the two (it counts the differences) and its rule the better measured
- A Go type is the methods one file gives it, so a type whose methods are spread over files is several containers. Fields are not compared at all, nor are Python methods named with double underscores, so two classes alike in `__init__` alone are not seen
- `x/new-sibling` is rare: 1 finding in 6,430 commits of 28 public repositories, in umami, joining a set read as yes. Run at ten older commits that each added a file to a set read above, it fires at five. Six firings say nothing of its precision, and none was read against what the author did next. A change that writes every site of a set at once is not reported, and many sets are born that way

## Pruning aids measured and not built

- Dead files, as a list of production files nothing imports. A prototype over the import graph listed 802 candidates on eight Python and TypeScript repositories after leaving out tests, manifest entries, declaration files, `*.config.*`, `conftest.py`, `__init__.py`, `__main__.py`, main guards, and Python scripts outside a package. Of 36 sampled, 3 were dead, 4 could not be told, and 29 were in use by something the graph does not see: a framework route or layout (5), an import from a `.vue` or `.svelte` file (5), a path alias (4), a script, benchmark, or example that a package script, a workflow, a `bin` entry, or an `index.html` runs (9), a codemod, fixture, or data module loaded by path (5), and a test double only tests import (1). It needs path aliases, workspace names, the non-TypeScript importers, and package scripts in the graph first. Go was left out: a package is a directory, and files of one package import nothing from each other.
- A score for which duplicate group to merge first, measured and not built. A rule fitted on the mined consolidation commits (longest identical token run, days since the later site was written, commits touching both files, same package) separated them from the pairs nobody merged at AUC 0.80. Tested forward on a tree it was not fitted on, with "unified within eight weeks" as the outcome, it ranked little better than chance, and so did `removable`
- Groups are rarely unified once they are written, whatever they look like, and new ones are written faster than old ones are merged. A finding when the copy is written reaches more than a ranking of what is already there
- Wide directories and long files need nothing new: a snapshot's directory rows carry `files` and its file rows carry `sloc`.
